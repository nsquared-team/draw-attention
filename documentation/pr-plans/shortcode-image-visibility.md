## Goal
Site owners who keep a Draw Attention image as a draft, private, pending, scheduled or password-protected stop having its hotspot text and picture shown to every visitor, and no existing site loses an unpublished image from its pages on the day it updates.

Focus of this PR: visitors see only images they may read, pages that show an unpublished image unchanged — a shortcode visibility check that spares unpublished images already shown only, nothing else.

Scope: `DrawAttention::shortcode()` in `public/class-drawattention.php` picks the newest image in any status and prints it without asking who is looking. The block, the Beaver Builder module and the single image view all call that one handler. In: after the image is picked, the handler returns nothing unless the image is published or the viewer may read it, and it returns WordPress's password form while a password is still owed. That form brings the visitor back to the page they typed the password on. Which image gets picked stays as it is. Existing sites: on the first load after the update the plugin stores, in the option `da_legacy_visible_images`, the images that are unpublished at that moment, since the shortcode showed them until now. Each of them skips the status check until its status next changes, whether its owner changes it or WordPress publishes it on schedule. A password gets no such pass: an owner who set one meant to protect the image, so the password form shows on every site from the update on. A notice on such an unpublished image's edit screen tells the owner in plain words that visitors can see it, and offers one link to hide it. Plus one end-to-end script and its CI step. Also in: CI's code sniffer skipped every PHP file under `admin/`, because its pattern for minified files also matched the word admin. The sniffer reads only PHP files, so the pattern goes. That workflow also starts with no access now: its one job may write code, its checkout keeps no token, and its last step logs git in for the one push of the formatter's fixes. ⏩ Out: honouring the `id` attribute; the Pro plugin's handler. Shape: about 100 lines across `public/class-drawattention.php` and `admin/class-drawattention-admin.php`, one new test script, one step in `.github/workflows/tests.yml` whose two checkouts stop keeping their token, one flag, a permissions block and a rewritten push step in `.github/workflows/ci.yml`, plus this file.
Risk: every front-end render of the plugin goes through this handler. An existing site whose image is unpublished keeps showing it, so that site stays exposed until its owner acts on the notice. A site that shows a password-protected image through the shortcode gets the password form in its place from the update on. A site that imports a newer unpublished image shows nothing to visitors until that image is published. Cached pages keep the old HTML until the cache clears. Undo: revert this PR; the stored option is then unused. The 1%: a published image with no password must render exactly as before, since that is nearly every site.

## Definition of Done
- [x] On a site that never showed an unpublished image, a visitor who is not logged in gets none of the image's hotspot text or picture from a page with `[drawattention]` while the image is a draft, pending or private.
- [x] On that site, while the image has a password, the visitor gets WordPress's password form and none of the image's content. The right password brings them back to the same page with the image.
- [x] A published image with no password renders for that visitor as it did before.
- [x] A logged-in editor still sees a draft image through the shortcode.
- [x] A site that already showed a draft image before the update still shows it to visitors after the update.
- [x] Once that image's status changes, or its owner follows the notice's hide link, visitors get it only when WordPress lets them read it.
- [x] `tests/e2e/shortcode-visibility.sh` fails against master's handler, passes on this branch, and runs in CI's end-to-end job.
- [x] No other code path in the plugin prints an image's hotspots to a visitor without going through this check.
- [x] CI's code sniffer reports on `admin/class-drawattention-admin.php`, and reads no minified file.
- [x] CI's formatting bot still pushes its fix to the branch, from a checkout that keeps no token.
- [x] A password-protected image asks a visitor for its password from the first load after the update, also on a site that showed it before, and its edit screen shows no notice.
- [x] When WordPress publishes a scheduled image on its own, that image's pass ends too, and its edit screen shows no notice.
